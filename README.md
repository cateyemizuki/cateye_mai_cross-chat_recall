# cateye_mai_cross-chat_recall —— 跨聊私聊回忆

让 bot 在必要情况下感知与指定群友的**私聊记录**：在群聊中按需把「与某群友的私聊概括」注入到 planner / reply 上下文，使 bot 能自然地"记得"与对方私下聊过的内容。全程区分群聊与私聊（扫描与注入只发生在群聊会话，私聊内容只读）。

## 行为定义

1. **扫描**：按配置的时机对群聊做一轮扫描——取群最近 N 条非 bot 消息汇总其中的用户 id（消息不足 N 条时回退为全量可用消息），逐个检查这些用户与 bot 的私聊是否满足总结条件。
2. **总结**：满足条件后把私聊内容交给 LLM 总结并写入插件自建 SQLite（`data/plugins/<plugin_id>/cross_chat_recall.db`）。请求体使用与官方一致的结构化上下文：system 提示词 + 一条 user 消息（只含用户与 bot 的消息，按时间排序，尾部附加总结要求），不包含任何其他内容。总结只由扫描触发。默认提示词要求按时间线列关键事件与时间点、覆盖最近一两次聊天、结尾列"需记住"关键信息，并以 `{bot_name}与{user_nickname}` 为主语；自定义提示词支持占位符 `{bot_name}` / `{user_nickname}` / `{user_id}`。
3. **注入**：把入库的概括按需注入群聊的 planner 与 reply 上下文（各自可开关，默认都注入），注入位置为第一条 SystemMessageItem 之后。注入内容包含：聊天起始/截止时间（精确到秒，如 `2026-09-29 21:31:16`）、与谁的聊天内容、聊天内容概括；多个用户合并为一个块。

## 扫描触发方式（三选一，`scan.trigger_mode`）

| 模式 | 触发点 | 说明 |
|---|---|---|
| `planner`（默认） | planner 触发时 | 在 planner 请求前对该群触发一轮扫描（后台执行，不阻塞 planner） |
| `push` | 消息推进时 | `chat.receive.after_process` 按群流计数新到的非 bot 消息（不含 bot/通知/命令/合成记录），达到扫描数即对该群触发扫描并清零 |
| `reply` | 触发回复时 | 只扫描被回复的目标用户：通过 reply 的消息 id 反查用户 id，再定向扫描该用户的私聊 |

## 总结触发条件（`summarize.*`）

- 总结时间窗口（默认 24 小时，可配）内**来自用户**的私聊消息数达到阈值（默认 5，不含 bot 消息）；超出窗口的消息一律不触发总结、也不进入 LLM 请求体。
- **重新总结**：距上次总结新推进（不含 bot 消息）的用户消息数达标（默认 5）后，不是立刻再总结，而是进入"可被重新总结"队列；再次被扫描到时才触发重新总结（**全量重写覆盖**，起止时间随新内容更新）。
- 总结配置：模型（默认 `replyer` 任务，可填具体模型名）、总结提示词（留空用内置默认）、最大 token 数。

## 注入用户选择（`inject.*`）

- planner：`trigger`（默认）= 触发 planner 的消息归属用户；`recent_users` = 触发 planner 的消息最近 N 条非 bot 消息的用户（N = `inject.recent_user_count`，默认 5，可修改）。
- reply：`reply_source`（默认）= 要回复的消息来源用户；`follow_planner` = 跟随 planner 选中的用户。

## 主动召回工具（LLM Tool `recall_private_chat`）

让 bot 在**用户明确要求**回忆与某人的私聊内容、或需要主动想起与某人私下聊过什么时，按昵称主动召回私聊概括（不会主动调用，也不在普通闲聊里调用）。工具默认走 deferred 池，由 `tool_search` 发现。

- **候选范围**：只查当前聊流最近 `tool.context_window_messages` 条消息（默认 50）里出现过的用户昵称，不做全库/全群搜索。bot 自身、通知、命令与合成消息不参与；昵称为空的用户不参与名称匹配；同一用户取最新昵称；只匹配昵称，不匹配 QQ 号。
- **名称解析五分支**（传入名称 strip 后为空按"名称有误"处理）：
  1. 精准匹配：`昵称 == 传入名称`；
  2. 精准未命中时正则降级：`re.search(传入名称, 昵称)`——昵称中包含与传入名称匹配的部分即可命中（如传入「星尘」可命中「星尘旅人」）；传入名称是非法正则时按字面量匹配；
  3. 命中 1 个 → 查询该用户的私聊概括；
  4. 命中 ≥2 个 → 返回候选精准名称名单（按最近发言新→旧去重），要求用户从中选一个重新查询，不附带任何私聊内容；
  5. 0 命中 → 返回"名称有误"。
- **召回结果**：该用户无记录、概括为空或概括已过 `store.summary_ttl_hours` → 返回"你和该用户没有私聊内容。"；有有效概括 → 返回与注入块同风格的内容（对象昵称、私聊起止时间精确到秒、概括正文），可直接转述。
- **粘性保留**：召回成功后，该用户的私聊概括会在这条聊流的 reply 请求中继续注入 `tool.recall_retention_minutes` 分钟（默认 5）；期间再次成功召回会刷新过期时间。粘性状态为内存态、不落盘，进程重启即清空。粘性注入只作用于 reply，受插件总开关与 `inject.inject_reply` 门控；粘性用户在工具调用时已过候选校验，注入阶段不再过群/用户黑白名单。

| 配置 | 默认 | 说明 |
|---|---|---|
| `tool.recall_retention_minutes` | 5.0 | 粘性召回保留分钟数（0.5–1440） |
| `tool.context_window_messages` | 50 | 名称候选取最近多少条群消息（5–200） |

示例：用户在群里问"你还记得私聊里「星尘旅人」说过什么吗？"，bot 即可调用 `recall_private_chat(user_name="星尘旅人")` 取回概括并转述（示例名称为虚构，实际以当前会话上下文中的昵称为准）。

## 命令

| 命令 | 作用 |
|---|---|
| `/ccr debug test` | 调试用（仅操作员）：在当前聊流的下一次 planner 与 reply 请求中，强制注入命令发起者的私聊回忆（绕过群聊/范围/开关检查；无总结时先定向扫描一次；标记 10 分钟有效，注入成功即消费） |
| `/ccr clean` | 清空插件私聊回忆总结库（仅操作员；同时清除强制注入标记） |

## 总结库管理

- 总结内容截止时间超出 `store.summary_ttl_hours`（默认 24 小时）后在扫描时删除，且不再注入。

## 作用范围（`scope.*`）

群白名单 / 群黑名单 / 用户白名单 / 用户黑名单（可选，默认全部为空 = 全放行）。黑名单优先于白名单；白名单非空时仅名单内生效。

## 调试日志

插件目录 `logs/cross_chat_recall.log`（DEBUG 级别，含扫描决策链、LLM 请求体与结果全文、注入块全文）。日志不被主动清除；文件日志不符合插件规范，现阶段仅用于测试，后续会移除。

## 本地开发

- 用 `MAIBOT_PLUGIN_SDK_PATH` 指向 SDK 仓库联调；manifest 变更需要完整重启 MaiBot。
- 运行期 `config.toml` 由 Runner 自动生成，勿提交。
